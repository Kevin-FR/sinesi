# J4 — Services en Rust

Le [profil portable](../agnostique/SERVICES_J4.md) définit le comportement et les limites. La [qualification](../verification/J4.md) et les registres lient vingt exigences à cinq tâches. Aucun paquet réseau, socket système ou moteur web généraliste n’est ajouté.

| Fichier | Rôle |
| --- | --- |
| `sns-model/src/services.rs`, `apps.rs`, `lib.rs` | DTO typés DHCP/DNS/HTTP, validation, profil 5 et commandes applicatives |
| `sns-protocols/src/dhcp.rs`, `lib.rs` | Automates client/serveur, UDP simulé, sondes ARP, offres/baux/refus, timers et projection effective |
| `sns-apps/src/dns.rs` | Résolveur, serveur, requêtes UDP à sockets éphémères, récursion/délégation et cache par hôte |
| `sns-apps/src/web.rs` | Cadrage HTTP, TCP, dossiers VFS, hôtes virtuels, formulaires, URL et état du navigateur |
| `sns-apps/src/lib.rs`, `terminal.rs` | Cycle des logiciels, routage des notifications, timers, host/nslookup/dnscache et résolution des noms |
| `sns-html/src/lib.rs` | Analyse contrôlée des documents réseau; le mode strict historique J0 est conservé |
| `sns-engine/src/lib.rs`, `applications.rs` | Initialisation DHCP et orchestration atomique des effets réseau/applicatifs |
| `sns-topology/src/lib.rs` | Promotion de profil sans rétrogradation lors des éditions suivantes |
| `sns-ui-egui/src/services_ui.rs`, `desktop.rs`, `lan.rs`, `lan_worker.rs` | Configurations natives, rendu HTML, ressources bornées et projection effective distincte du document |
| `sns-i18n/locales/messages.json` | Catalogue explicite des six langues |
| `contracts/*services*.schema.json`, `fixtures/valid/services.json` | Contrats portables : projet 5, événements 6, commandes API 1 et exemple embarqué |

DHCP est une fonction réseau du dispositif, pas un quatorzième logiciel. `Network` conserve les attributions et une projection réseau partagée par `Arc<Project>`, invalidée à chaque changement d’adresse. La sauvegarde utilise toujours le document de base. La projection du worker est séparée de celle transmise à l’éditeur; les logiciels et fichiers ne figent pas les adresses acquises.

Les tables et les collections sont ordonnées; les jetons de requête/navigation rendent les délais anciens inertes. Les délais traversent le même plan transactionnel que les segments TCP, datagrammes et faits. Les dates DHCP utilisent une addition contrôlée et les caches saturent leurs échéances sans débordement. Les sessions sont fermées à expiration du bail, arrêt/désinstallation du service ou nouvelle navigation.

Les caches DNS sont indexés par hôte/nom/type. Les caches d’image sont dans chaque vue du navigateur, indexés par URL complète et vidés à chaque génération; les textures natives suivent cette génération. Le décodage réutilise `image` déjà verrouillé dans le projet, avec dimensions 4 096 × 4 096 et allocation 64 Mio maximum. `sns-html::parse_network` permet les références HTTP/relatives et conserve la liste des éléments/attributs autorisés; `parse` garde les restrictions historiques du prototype.

DHCP et DNS sont des modèles de messages structurés sérialisés dans le corps UDP; HTTP est cadré sous forme d’octets HTTP/1.1 sur le transport existant. Il n’y a pas de conformité binaire BOOTP/DNS revendiquée. Les extensions Java de Filius sont remplacées par une route POST déclarative qui échappe les valeurs.

Essai : `cargo run -p sns-desktop --locked --offline`, menu **Exemples réseau**, **DHCP, DNS et pages web**. Démarrer les deux services depuis le bureau du serveur, avancer la simulation, puis ouvrir le navigateur d’un client. Les réglages DHCP s’éditent en conception; les réglages DNS et HTTP dans les fenêtres des logiciels. Le serveur HTTP doit être arrêté pour changer son port/dossier.
