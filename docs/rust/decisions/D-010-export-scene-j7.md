# D-010 — Scène documentaire et glyphes hors widgets

Date : 8 novembre 2026. Mise en œuvre pour F-DOC-003 dans RS-REPORTING-J7; PDF non encore réalisé.

`sns-render` est une bibliothèque pure : elle prépare `Scene`, ses `Item`/`Primitive` et `Bounds`, puis renvoie `PngImage` sans ouvrir de fichier. L’instantané est validé; `complete_positions` est partagé avec `Editor` pour la disposition initiale, sans recréer un éditeur ni recopier les applications/fichiers dans la scène. Les libellés effectifs optionnels sont une projection distincte, validée par identité; ils ne changent jamais `Project`. `network_art.rs` et le backend CPU prennent leurs SVG dans le même `symbol_svg`.

La chaîne réutilise **resvg/usvg 0.45.1 et tiny-skia 0.11.4**, déjà fixés pour les symboles. La proposition initiale 0.12 reste une cible à réévaluer si nécessaire, pas une version prétendument compilée. Partager le raster existant évite deux familles de types et une nouvelle résolution de paquets. Les fonctionnalités de polices système et d’images externes ne sont pas activées pour le rendu de plan; les deux résolveurs d’images SVG renvoient explicitement `None`. Les seules entrées SVG sont les vingt assets compilés, pas des ressources du projet. Références : [resvg](https://docs.rs/resvg/0.45.1/resvg/), [tiny-skia](https://docs.rs/tiny-skia/0.11.4/tiny_skia/).

`sns-fonts` ajoute **HarfRust 0.12.0 et skrifa 0.44.0**, déjà dans le lockfile d’egui. Le premier produit identités, avances, offsets et groupes de glyphes; le second fournit métriques et contours. Les positions sont converties depuis les unités par em. Les quatre fontes Noto sont les mêmes que pour les annotations à l’écran. Les données de shaping sont initialisées une fois; les contours normalisés à la taille 1 sont mis en cache par face/glyphe pendant l’export, puis transformés pour chaque taille. Les lignes gardent leur texte et leurs indices UTF-8 locaux, utiles au futur backend PDF. Référence de contours : [skrifa](https://docs.rs/skrifa/0.44.0/skrifa/outline/index.html); le README et les sources HarfRust 0.12.0 du registre local ont été lus pour l’API réellement compilée.

La mise en page gauche à droite reste bornée et explicite : pas de fallback système, ni promesse bidi/thaï par la seule présence d’un shaper. Un glyphe absent est une erreur transactionnelle d’export. Les débordements logiques de texte sont comptés. Origine de texte et masque de découpage sont distincts : les jambages et l’inclinaison peuvent utiliser la marge sans être coupés au premier caractère. L’écran découpe également les notes au cadre extérieur. Les règles et quotas sont dans le [profil portable](../../agnostique/EXPORTS_J7.md).

Le PNG emploie une image principale RGBA, des tuiles/masques locaux pour le texte et une marge de sortie de 16 pixels, indépendante de l’étendue du monde. La dimension maximale est 4 096; le budget de tracés et de glyphes est contrôlé avant de laisser grossir les caches. `Scene` n’a pas de désérialisation publique : ce profil n’accepte pas une scène ou un SVG arbitraire fournis par un document.

`export_ui.rs` utilise un fil et un canal borné pour la sélection native asynchrone (`rfd` + `pollster 0.4.0`, déjà résolu), puis un autre travail pour scène/rendu/écriture atomique. Le thread GUI reste disponible; il réserve la destination et attend le travail à la fermeture normale. La capture lit la dernière vue confirmée du worker, notamment les étiquettes DHCP, sans lui envoyer de commande réseau. `render_cli.rs` expose le même backend sur un projet statique. Le lockfile ajoute seulement le crate local `sns-render` et de nouveaux liens directs, sans nouvelle version tierce.

Le lecteur de preuve `check_png_exports.py` utilise uniquement la bibliothèque standard Python et une reconstruction indépendante des filtres PNG. Il ne réutilise ni resvg ni le décodeur d’images Rust. Le [rapport](../../verification/J7-PNG.md) relie les images et tests au registre. Les limites de performance globales, le backend PDF et la preuve native sur trois OS restent ouverts.
