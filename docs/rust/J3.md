# J3 — Routage et représentations pédagogiques en Rust

Le comportement indépendant du langage est défini dans [ROUTAGE_J3](../agnostique/ROUTAGE_J3.md). La [qualification J3](../verification/J3.md) relie 15 exigences (14 de la roadmap et F-TOP-011 demandée pour les assets) à sept lots; les chemins réels restent dans [taches.json](taches.json).

| Fichiers | Responsabilité |
| --- | --- |
| `sns-model/src/routing.rs`, `lib.rs` | Routes statiques typées, options de transfert/RIP, symboles, profil 4 et validation avant usage |
| `sns-protocols/src/routing.rs` | Routes configurées/apprises, origine, expiration, sélection déterministe et prochain saut |
| `sns-protocols/src/forwarding.rs` | Transfert commun ICMP/TCP/UDP, TTL, encapsulation, erreurs de retour et ARP explicite |
| `sns-protocols/src/rip.rs`, `rip_tests.rs` | Annonces UDP structurées, validation, candidats par voisin, timers, poison reverse et tests de rejet |
| `sns-protocols/src/transport.rs` | Choix d’adresse source depuis la même table de routage que le transfert |
| `sns-engine/src/lib.rs` | Démarrage RIP dans la file virtuelle, contrôle de suspension transactionnel, génération isolée |
| `sns-topology/src/lib.rs` | Redimensionnement, échange de ports, protection des connexions/routes, undo/redo |
| `sns-apps/src/lib.rs`, `terminal.rs` | route, arpsend, job traceroute à jeton et collecte des faits ICMP, interruption |
| `sns-ui-egui/src/routing_ui.rs`, `lan.rs`, `lan_worker.rs` | Configuration, tables avec métriques/dates, projection runtime, explication des décisions et exemples |
| `sns-ui-egui/src/network_art.rs`, `assets/network/` | 14 SVG embarqués, textures mises en cache, deux styles et symboles persistants |
| `sns-i18n/locales/messages.json` | 336 clés × six langues; aide, erreurs et contrôles J3 |
| `contracts/*routing*.schema.json` | Projet 4, événements 5 et contrôle RIP API 1 indépendants des types Rust |

La pile conserve son sens de dépendance. `sns-protocols::Routing` ne dépend ni des applications ni de la GUI. Les services et le terminal consomment les faits du même moteur; ils n’appellent aucun routeur ou shell réel. Les effets RIP, ARP et traceroute sont préparés par le plan transactionnel existant : une erreur de quota/date ne publie pas un état partiel.

La file initialise les routeurs RIP dans l’ordre de leurs identifiants. Les routes/candidatures utilisent des collections ordonnées et des départages explicites. Le test de déterminisme compare les octets avec dispositifs/liens/interfaces inversés et des budgets de traitement d’un événement. Les dates d’expiration sont exprimées en microsecondes virtuelles; les champs exportés utilisent les décimaux exacts du modèle.

Le job traceroute utilise un token de génération locale, des corrélations par TTL, une sonde puis un timer de collecte. Les faits réseau mettent à jour ses résultats; les timers d’un job interrompu deviennent inertes. Les erreurs ICMP de retour conservent la corrélation initiale même après un échec ARP sur un routeur intermédiaire. L’ajout/modification de logiciels/fichiers ne rétrograde plus un document de profil 4 vers le profil 3.

Les options de configuration sont éditables en conception, les tables dynamiques et la suspension des annonces sont disponibles en simulation. Les ports retirés ne doivent être ni câblés ni référencés par une route. Les commandes de réaffectation changent les liens, sans échanger silencieusement les adresses IP/MAC.

Le rendu SVG active uniquement la fonctionnalité `svg` d’egui_extras 0.37, qui fournit les helpers CPU resvg 0.45.1; aucun chargeur d’images réseau n’est installé. Le lockfile conserve les versions effectivement compilées, dont tiny-skia 0.11.4 pour ce chemin. Les assets choisis sont copiés depuis le kit fourni vers `assets/network`, leurs hashes sont dans `provenance.json`, et leur lecture est intégrée par `include_bytes!`. `scripts/check_network_assets.py` vérifie inventaire, SVG et absence de référence externe; le manifeste de code couvre désormais aussi les SVG et assets. Les textures de 256 × 256 sont calculées une seule fois par style/symbole et mises en cache.

La vue Schéma emploie un fond clair, des traits contrastés et des libellés bornés; les noms complets restent accessibles. Les libellés courts des routeurs/commutateurs sont placés dans le symbole. Les représentations d’hôtes sont des rôles graphiques persistants; leur modèle réseau reste celui d’un hôte IPv4, sans inventer un backend d’impression ou sans-fil.

Pour essayer : `cargo run -p sns-desktop --locked`, menu **Exemples routés**. Choisir **Salle de classe**, **Trois réseaux et routes statiques** ou **Trois routeurs et RIP**. Basculer **Icônes/Schéma**. Pour traceroute : exemple statique, Simulation, Bureau A, Terminal, `traceroute 192.168.30.2`, puis Reprendre ou pas à pas. Dans l’inspecteur d’un routeur RIP, métrique 16 signifie inaccessible; suspendre les annonces puis avancer au-delà de 75 secondes virtuelles rend le retrait observable.
