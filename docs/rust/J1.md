# Adaptateur Rust — réalisation J1

Comportement de référence : [LAN_J1](../agnostique/LAN_J1.md). Suivi exécutable : [taches.json](taches.json) et [features.json](../suivi/features.json). Les `actual_paths` relient chaque lot aux fichiers réalisés.

| Lot | Implémentation |
| --- | --- |
| RS-TOPOLOGY-J1 | `sns-topology::Editor` et `Edit` : validation transactionnelle, révision, identités/MAC, historique borné; `sns-ui-egui::LanUi` : canevas Painter, transformation monde/écran, sélection, dépôt, câblage, raccourcis |
| RS-DEVICES-J1 | DTO dans `sns-model`, palette dans `sns-topology`, inspecteur par interface et identité persistante |
| RS-ENGINE-J1 | `sns-engine` conserve la file unique; `pump` avance sans sérialiser la trace entière; `tick_network` prépare sur un clone et valide quotas/dates avant commit |
| RS-LINK-J1 | `sns-protocols::Network` : Ethernet, SAT, cache ARP, résolutions groupées, expirations gardées et déduplication bornée |
| RS-IPV4-J1 | `sns-protocols` : adresses `Ipv4Addr`, sous-réseaux/masques/next-hop, loopback, echo et erreurs ICMP; pas de sockets OS |
| RS-PROJECTS-J1 | `sns-project` conserve les sauvegardes atomiques bornées; `rfd 0.17.2` verrouillé pour les dialogues; `scripts/inspect_filius.py` inventorie seulement le corpus, sans import Java |
| RS-QUALITY-J1 | Contrats autonomes LAN, fixture R-LAN, tests du moteur/éditeur/CLI/UI, arbre accessible et snapshots, mesure CPU/mémoire de référence |

Le moteur appartient exclusivement au thread `sinesi-lan`. Le thread de rendu possède le document éditable; la simulation reçoit un clone validé lors de son démarrage. Il n’existe aucune référence mutable vers le moteur dans les widgets. La publication réveille le contexte graphique; au repos, le worker attend une commande sans imposer une cadence de rendu. Le canal de commandes est borné à 16; la projection en transit à une seule valeur, avec remplacement par la plus récente. Les erreurs de file pleine sont visibles. Les dialogues de fichiers sont synchrones et modaux côté application; ils ne bloquent pas le thread moteur.

L’adaptateur de présentation demande des bornes virtuelles depuis `Instant`, par lots maximum de 128 événements. Il conserve une borne indépendante du dernier événement et remet sa base à zéro lors d’une pause/reprise; les protocoles n’importent pas d’horloge réelle. Les tests utilisent une barrière dédiée plutôt qu’un délai arbitraire. Une pause ne consomme aucune minuterie. Les purges sont des commandes administratives synchrones et idempotentes, tracées au temps courant.

Les événements LAN utilisent les mêmes priorités de livraison et le même générateur de jitter que J0. Chaque effet conserve l’index de son fait d’émission : sa cause ne pointe pas vers l’émission d’un autre port. Les transactions copient l’état réseau avant planification; c’est simple et vérifiable, mais coûteux sur les fortes charges. Les mesures publiées concernent le profil dev; une optimisation par journal de changements devra préserver les tests de rollback et de trace.

L’application démarre dans `LanUi`. `SinesiUi` et ses tests conservent le prototype J0 de navigateur pour qualification; il ne représente pas un navigateur HTTP au-dessus de la pile LAN. Les modules Craft, forks de fenêtre, exports PDF/PNG produit et shaping avancé ne sont pas introduits dans ce lot.

## Exécution et vérification

```sh
cargo run -p sns-desktop --locked
cargo run -p sns-cli --locked -- ping fixtures/valid/lan.json --source host-a --target 192.168.1.3 --count 2 --trace target/lan.jsonl
cargo test --workspace --locked
cargo test -p sns-ui-egui --features ui-snapshots --test lan --test workbench --locked
cargo test -p sns-ui-egui --lib reference_load --locked -- --ignored --nocapture
python3 scripts/check_layers.py
python3 scripts/test_filius_inspection.py
python3 scripts/inspect_filius.py _archive/filius-master/beispiele/*.fls
python3 scripts/docs.py render
python3 scripts/docs.py check --require-reference
```

La recette de charge est dans `fixtures/lan_load.rs` : 50 hôtes, 50 switches, 150 liens dont des boucles, 40 sondes initiales, budget exactement 10 000 événements. Le budget est atteint volontairement; ce benchmark n’affirme pas que la charge est vidée. Le test de terminaison d’une boucle est une recette distincte. La mesure UI utilise 100 frames de calcul egui avec arbre accessible, sans GPU ni temps d’affichage; la mémoire maximale est mesurée sur le processus de test compilé, sans compilateur. Voir le [rapport et les journaux](../verification/J1.md).
