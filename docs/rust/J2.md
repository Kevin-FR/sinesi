# J2 — Réalisation Rust

Le comportement portable est dans [HOTES_J2](../agnostique/HOTES_J2.md) et [TRANSPORT_J2](../agnostique/TRANSPORT_J2.md). Les six lots J2 relient 40 exigences aux fichiers et preuves dans [taches.json](taches.json). La qualification locale est décrite dans le [rapport J2](../verification/J2.md).

| Couche | Fichiers effectivement réalisés |
| --- | --- |
| DTO portables | `sns-model/src/transport.rs`, `sns-model/src/apps.rs` : sockets, notifications, catalogue, commandes applicatives/fichiers |
| LAN et transport | `sns-protocols/src/lib.rs`, `src/transport.rs` : machines à états, encapsulation, ARP/ICMP et timers |
| Applications | `sns-apps/src/lib.rs`, `src/terminal.rs` : registre, service echo, clients, jobs, commandes et journaux structurés |
| Fichiers | `sns-vfs` : arbre transactionnel, blobs `Arc<[u8]>`, codec `VirtualFile` |
| Orchestration | `sns-engine/src/applications.rs` : préparation d’un plan sur clones, consommation immédiate des notices socket, contrôle global puis commit |
| Document | `sns-topology::Editor::accept_applications` : fusion des installations/fichiers dans l’historique, conservation de la géométrie et du profil 3 |
| Interface | `sns-ui-egui/src/desktop.rs`, `lan.rs`, `traffic.rs` : bureaux/fenêtres, édition de fichiers, rendu image et observations |
| Worker | `sns-ui-egui/src/lan_worker.rs` : propriétaire unique du moteur, projections bornées, epoch, révision et compteur de commandes appliquées |
| Langues | `sns-i18n`, `sns-settings`, `scripts/check_i18n.py` : 274 clés × six langues, diagnostics structurés, préférences atomiques hors projet |

Le graphe reste orienté : protocoles → modèle; applications → protocoles/modèle/VFS; moteur → applications/protocoles. Le cœur ne dépend ni d’egui, ni des dialogues, ni d’un runtime de sockets OS. Les notifications sont consommées après chaque traitement réseau, avant que le traitement suivant ne remplace leur tampon. Le serveur echo produit un effet `SocketCommand::Send`; les livraisons continuent dans la même file de temps virtuel.

`Engine` partage la configuration par `Arc<Scenario>` pour éviter une copie profonde à chaque tick. Le plan copie les états modifiables, contrôle dates, séquences, trace/file et quotas avant d’appliquer quoi que ce soit. Les causes des effets réseau sont décalées lors de l’assemblage des faits applicatifs. Les jobs ping/capture ne consultent pas l’horloge réelle. Les timers de jobs portent un jeton qui rend les timers d’un job interrompu inertes.

La GUI reçoit `Project`, `HostView`, sockets et trace du worker. Une epoch empêche le retour d’un ancien document après Nouveau/Ouvrir. Le compteur de commandes appliquées bloque une sauvegarde prématurée. La géométrie reste gérée par l’éditeur; la fusion applicative ne l’écrase pas. Les fenêtres restent sous les commandes de simulation et les brouillons sont conservés jusqu’à succès de sauvegarde ou abandon explicite. Les textures des applications désinstallées sont relâchées.

Le rendu d’images utilise `image 0.25.10`, fonctionnalités PNG/JPEG/GIF/BMP du lockfile, avec limites de décodeur, puis une texture egui. L’import et les dialogues système sont dans l’adaptateur GUI. Les dialogues `rfd` sont actuellement modaux; le moteur demeure sur son worker et ne dépend pas de cette modalité. L’I/O du fichier choisi est bornée à 1 Mio. Une généralisation à des imports lourds devra déplacer aussi la lecture hors de la frame.

Le module `traffic` contient des filtres de présentation et l’export TSV UTF-8. L’historique canonique n’est pas purgé; seule la borne de vue change. Les quatre couches affichent les sous-objets des faits historiques, sans reconstruire un paquet depuis la configuration courante. Les couleurs de liens sont des effets de présentation éphémères.

Pour essayer : `cargo run -p sns-desktop --locked`, **Exemple logiciels**, **Simulation**, **Bureau**. Le projet `fixtures/valid/hosts.json` fournit les logiciels et fichiers de démonstration. Dans Portable B, ouvrir/démarrer Serveur echo; dans Poste A, ouvrir/connecter Client TCP au port 7777, puis reprendre ou avancer la simulation. Le sélecteur de langue est toujours accessible.

Validation : `cargo test --workspace --locked`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, tests GUI avec `ui-snapshots`, puis contrôles d’architecture, i18n et documentation. Les benchmarks et preuves J0/J1 restent historiques. DNS/HTTP/J3+, reprise complète des sessions et connectivité entre instances ne sont pas ajoutés à J2.
