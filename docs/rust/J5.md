# J5 — Réseaux privés et filtrage en Rust

Le [profil portable](../agnostique/RESEAUX_PRIVES_J5.md) est la référence des comportements. La [qualification J5](../verification/J5.md) et les registres relient 17 exigences à six lots. Aucun runtime réseau, socket système ni bibliothèque supplémentaire de réseau n’est introduit.

| Fichiers | Responsabilité |
| --- | --- |
| `sns-model/src/security.rs`, `lib.rs`, `services.rs`, `apps.rs` | Rôles LAN/WAN, règles et redirections typées, validation, commandes et profil 6 |
| `sns-protocols/src/nat.rs` | NAPT par endpoint/correspondant, ports réservés, ICMP, copies encapsulées, purge et expiration |
| `sns-protocols/src/firewall.rs` | Décisions entrantes, première règle, modes SYN/UDP/ICMP et journal borné |
| `sns-protocols/src/lib.rs`, `forwarding.rs`, `dhcp.rs`, `transport.rs` | Ordre des hooks, erreurs ICMP citées, rôles Gateway, allocation par interface et conservation des services LAN à expiration WAN |
| `sns-apps/src/admin.rs`, `web.rs`, `lib.rs` | Pages internes via les sockets HTTP, formulaires validés, contrôle des versions et cycle du logiciel pare-feu |
| `sns-engine/src/applications.rs`, `lib.rs` | Plan transactionnel avec document emprunté/modifiable, application commune des commandes natives et HTTP, démarrage des services internes |
| `sns-topology/src/lib.rs` | Création des deux interfaces/services et conservation du profil; synchronisation des paramètres runtime vers le document de l’éditeur |
| `sns-ui-egui/src/security_ui.rs`, `lan.rs`, `desktop.rs`, `lan_worker.rs`, `traffic.rs` | Édition commune, tableaux vivants, purge, rôles visibles, worker et couches de trace |
| `sns-i18n/locales/messages.json` | Six traductions explicites pour les panneaux et les pages internes |
| `contracts/*private*.schema.json`, `security-command.schema.json` | Projet 6, événements 7 et API 1, indépendants du langage |
| `fixtures/valid/private.json` | Exemple LAN/WAN, routeur amont sans route privée, redirection 8080→80 |

Le moteur reste l’auteur unique de l’état. `ApplicationPlan` emprunte le projet par `Cow<Project>` tant qu’aucune modification n’est nécessaire; les effets d’administration le copient avant validation. Document, révision, réseau, logiciels, faits et événements sont publiés ensemble après les contrôles de quotas et de dates. Une erreur ne laisse ni règle ni mapping partiel. Les enveloppes natives gardent leurs gardes de génération/révision; les formulaires utilisent en plus une empreinte non cryptographique contre les éditions obsolètes.

NAT utilise une collection ordonnée de mappings à identifiant interne, une recherche déterministe de ports et un ensemble des ports réservés. Les candidats ne sont pas recalculés par clonage des sockets pour chaque port. Un timer d’expiration par entrée est reprogrammé si son échéance a été rafraîchie; le trafic ne crée pas un timer d’inactivité supplémentaire à chaque segment. Les dates sont vérifiées contre les débordements.

`Icmp.quoted` contient une copie bornée par les chemins producteurs du paquet à l’origine d’une erreur. Il reste absent dans les profils historiques; sa présence et les nouveaux faits utilisent le schéma d’événements 7. `nat_original` retrouve le paquet privé avant de générer une erreur d’échec ARP WAN. Les trames existantes et les valeurs de la trace ne sont pas modifiées.

La projection DHCP garde ses rôles par identité d’interface; le cache de projet effectif est invalidé après une modification de configuration. L’expiration d’adresse ferme les sockets liées à cette interface et les requêtes UDP éphémères, sans fermer les écoutes génériques ou les connexions sur le LAN intact. Le changement WAN purge les mappings. Les applications de passerelle sont admises par le même transport que les hôtes/routeurs.

Le worker publie séparément le document, le projet effectif, les mappings et les décisions. `Editor::accept_applications` synchronise aussi les configurations NAT/pare-feu; il conserve la géométrie et les adresses configurées. Les brouillons inchangés se rafraîchissent après une administration web; les brouillons modifiés signalent le conflit et demandent un rechargement. Les identifiants des nouveaux panneaux restent stables au changement de langue.

`sns-apps` réutilise `sns-i18n`, qui reste indépendant de la GUI, pour les pages internes. Le serveur et le navigateur gardent les mêmes limites de cadrage HTTP et HTML que J4. Les règles et journaux sont paginés. L’administration n’est pas une extension exécutée depuis le VFS; ses opérations sont une liste de commandes déclaratives.

Essai : `cargo run -p sns-desktop --locked --offline`, **Exemples réseau → Réseau privé, NAT et pare-feu**. En simulation, ouvrir le navigateur de Poste A et saisir `http://192.168.10.1/admin`. Le service interne est déjà actif. Pour le NAT, envoyer un ping vers `198.51.100.10`, sélectionner le routeur domestique et ouvrir **Réseau privé LAN/WAN**. Pour publier HTTP LAN, démarrer le serveur web de Poste A puis utiliser `http://203.0.113.2:8080/` depuis le WAN.
